# Spaceship Architect v0.3 — local implementation report

Completed September 28, 2026. Local only: no commit, push, deployment or save migration. Earlier SIC, map, shield and Cleanser changes remain intact. Gold Standard and Vector were not changed.

## Main menu and campaigns

- The large, centered Join Active Room field is the primary entry. Load Campaign, Create New (campaign, character or starship), Tutorial / Explore Features, remembered tutorial help, and the bottom-right v0.3 label are present.
- Loading a v0.3 campaign file grants GM access. If its room is running, choose Enter Current Room or Update Room from File.
- Room codes are stable and changeable in GM Settings. Close Room closes access for everyone; a GM disconnect alone does not close it.
- Joining asks for the player's first name, which fills the character's player-name field. The lobby shows character availability and PC-controlled ships and permits spectating before linking.
- Character passwords are unrestricted visible text, including empty passwords. One player holds one character, and another player cannot claim it. Links survive refresh/restart. The GM can view passwords and assign unlinked players.
- Abandon Character releases the player without deleting the character. Creating/importing another character requires abandoning first.
- Native campaign character creation is immediately playable after the password step. Portable character imports need GM review/approval, followed by the importing player's password choice. The GM accepts or rejects the submitted data as-is.
- Portable exports omit access credentials and campaign membership while retaining statistics. Standalone characters can allocate creation EXP but obtain weapons/gear after joining a campaign. Standalone character/ship linking uses the approval workflow.
- Starships have no player password. Imported ships need GM approval. Crewing is GM-only; assigned PCs may upgrade the ship.
- Server persistence retains sessions. GM browser recovery copies use IndexedDB; reconnect/recovery paths reuse the room when possible. Campaign files include characters, ships, passwords, encounter, settings and statistics, but omit runtime browser sessions.
- Spectators receive combined PC-ship knowledge, excluding hidden enemy ships, crew, interiors and unseen objects.

## Ship construction and saved floorplans

- The construction sidebar shows the three latest purchased SICs; the categorized Purchased SIC gallery holds the complete inventory.
- Owned cards expose their applicable Locate, Install, Remove, Store, Sell, Destroy, Refund and Duplicate actions beside the card on desktop. Existing placement/refund rules remain.
- Confirm Changes compiles the static high-resolution interior into a saved WebP image. Crew, doors, stations, routes, oxygen and other changing overlays stay live.
- Snapshots are bounded to 2,048 pixels per edge and roughly two million pixels, with a bounded cache. Layout changes invalidate them. Invalid/unavailable snapshots fall back to the original rendering.
- The test Cleanser ship produced a 1,409 × 1,487 snapshot, about 229 KB of image data. Confirmation, fleet reopening and server restart retained it.
- Removed Hull view from combat; construction/details still offer it.
- Shared revisions prevent stale editors from overwriting confirmed changes. Other editors exit with a notice. Cancel Upgrade restores the entire confirmed ship, including its name, and exits the embedded editor without spending pending purchases.

## Console, hacking and Cleanser fixes

- GM-controlled NPCs have the fixed gold Console View button, with a chooser for multiple available operators.
- The Cleanser station fills the viewport and retains its reactor, charge, waveform, ATB and final-charge effects.
- Hacking accepts duplicate letter guesses and avoids double-counting feedback. Captured Cleanser consoles expose Shut Down Captured SIC through the existing hacking command.
- Sensor range is required when activation begins. The original aim hex then stays fixed even if the target leaves range. A starship at least three hexes away escapes. Layered shields and discarded overflow remain unchanged.
- Waiting damage screens offer Return to Combat and a reopen control, avoiding the operator-wait trap.
- The sequence remains Roll Damage → standard dice spectacle → final result → Confirm and Submit → sound/explosion → aftermath.
- The cosmetic Cleanser spectacle uses 96 existing D12 models and cheaper cosmetic physics instead of 192. Its 20,000D12 result remains explicitly simulated. Ordinary dice and Ship AI keep the established renderer.
- Replaced console Hold's blocking browser confirmation with an in-app dialog after the nested confirmation stalled a test view. The replacement was verified through to Resume.
- Play-view fitting excludes unseen scenery; GM object-placement tools remain available.

## Movement, character reference and statistics

- Assigned PC ship views have a WASD / Arrow Keys toggle, supporting upper/lowercase letters. It reuses normal mesh routes, speed and actual doors, and ignores typing fields, dialogs, active movement, combat and incapacitated characters.
- Fixed first keyboard movement without a saved location. Shared crew positions update and survive reloads, providing deployment starting locations.
- Added the fixed right-side Character Sheet drawer outside the sheet tab. Attributes open first; clicking the active tab retracts it. Attributes/Skills use the normal roll interface; other tabs are reference-only. Compact dice rows fit the drawer, which stays below roll dialogs.
- PC Settings statistics track confirmed roll counts/average final scores, largest personal hit dealt/taken, and lifetime EXP/Reverence earned. Unrolled standard skills show zero and no average. Statistics travel with character exports; retry receipts prevent duplicates. Ship damage is excluded from personal attack records.
- Fixed attribute-only rolls passing a missing skill to the resolver.
- After the first creation-decimal roll, a fading Skip button reveals remaining decimals together and finishes normal creation. It preserves an already-resolved in-flight result.
- Rules decision: the existing decimal system uses D10, not D6. The established distribution and racial rules were preserved; Skip changes presentation only.

## GM Quick Prompt

- Bottom-left composer: Attribute, Skill, integer Difficulty, recipients and saved name.
- One column per PC plus Everyone, targeting all campaign characters. Ten preset slots per column, initially Awareness, Computer, Persuade, Self-Control and Athletics at difficulty 10.
- Independent difficulties persist across sessions. Any preset can be deleted; +1 Reverence remains permanent and respects the cap.
- Requests use the existing dice interface and process oldest first. Saves/sends queue rather than dropping rapid changes, and updating presets preserves the composer draft.

## Limits and recommended playtesting

Testing was local, not hosted or across multiple physical devices. Long network outages, actual multi-device editor contention, mobile layouts and low-end frame rates were not exhaustively measured. Snapshots reduce repeated artwork but preserve live interactive elements; performance will still vary by machine. Tutorial mode supplies introductory help, not a complete guided campaign.

Prioritize two players editing one ship, disconnect/rejoin, importing a character, the reference drawer during play, and a PC Cleanser firing while other players watch. This pass did not manually replay every older SIC feature.

## Launch

Restart the normal Spaceship Architect server, then refresh. Use Start Spaceship Architect / START SA ATB MULTIPLAYER.cmd and open **http://127.0.0.1:8790/index.html**. The isolated test server was stopped. Start a fresh v0.3 campaign; older campaigns were not converted or deleted.
